# Plan

## 언제 쓰나
- 새 기능 시작, 여러 파일에 걸친 변경, 접근이 불확실할 때.

## 절차
1. **목표 정리** — 무엇을, 왜 만드는지 한두 문장.
2. **현재 상태 파악** — 관련 코드/제약 조사. 추측하지 않는다.
3. **접근안 제시** — 방식 1~2개와 트레이드오프.
4. **작업 분해** — 테스트 가능한 단위로.
5. **CONFIRM** — 계획을 확인받은 뒤 구현으로.
