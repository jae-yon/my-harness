## Plan

### 사용 시점
- 새 기능 시작, 여러 파일에 걸친 변경, 접근이 불확실한 경우

### 절차
1. **목표 정리** — 무엇을, 왜 만드는지 하나의 문장으로 정리한다.
2. **현재 상태 파악** — 절대 추측하지 않고, 관련 코드/제약을 조사한다.
3. **접근안 제시** — 방식 1~2개와 트레이드오프를 제시한다.
4. **작업 분해** — 테스트 가능한 단위로 나누고, 각 단계에 검증 방법을 명시한다:
   ```
   1. [단계] → 검증: [확인 방법]
   2. [단계] → 검증: [확인 방법]
   ```
5. **최종 승인** — 계획을 확인받은 뒤 구현으로 진행한다.
