## Design Taste

### 사용 시점
- 새 UI 컴포넌트/화면을 작성할 때.
- 구체적인 방향 없이 "더 예쁘게 만들어줘" 요청을 받았을 때.

### 절차
1. **완전히 새로운 페이지/화면일 때만** (기존 컴포넌트 수정에는 생략) — 설계하기 전에 같은 유형의 화면 레퍼런스를 2~3개 조회한다. 브라우저 또는 WebSearch로 Mobbin(mobbin.com, 실제 출시된 프로덕트 화면·플로우)과 Dribbble(dribbble.com, 비주얼·컴포넌트 단위 컨셉)을 둘러본다. 빌려올 만한 구체적인 레이아웃·패턴을 메모해두고, 백지 상태에서 바로 설계하지 않는다.
2. **기존 기준을 먼저 찾는다** — 새 간격·색상·radius·폰트 값을 만들기 전에, 이미 쓰이고 있는 디자인 토큰(Tailwind theme/config, CSS 변수, 또는 `components/ui/`에서 가장 많이 쓰이는 shadcn 컴포넌트)을 확인한다.
3. **있으면 재사용, 없으면 하나만 추가** — 필요를 충족하는 토큰이 있으면 그걸 쓴다. 없으면 일회성 인라인 값을 넣지 말고, 공유 소스에 토큰 하나를 추가하자고 명시적으로 제안한다.
4. 아래 기본 규칙을 적용한다.
5. 디자인 판단이 정말 불확실하면 추측하지 말고 트레이드오프를 밝히고 물어본다 (AGENTS §1 참조).

### 기본 규칙
- **간격(Spacing)** — 하나의 스케일(예: Tailwind 기본 4px 그리드)을 고수한다. `13px`/`22px` 같은 임의 값을 스케일과 섞지 않는다.
- **타이포그래피** — 화면 하나에 폰트 크기/굵기는 보통 2~3개면 충분하다. 라벨 하나 때문에 새 굵기를 추가하지 않는다.
- **색상** — 원색 hex나 임의의 Tailwind 색상 대신 팔레트의 시맨틱 역할(primary/muted/destructive 등)을 쓴다. 색이 있거나 어두운 배경 위에 저대비 회색 텍스트를 절대 놓지 않는다.
- **radius·shadow** — 프로젝트당 radius 스케일 하나, shadow 스케일 하나만 쓴다. 이유 없이 형제 요소에 `rounded-md`와 `rounded-xl`을 섞지 않는다.
- **모션** — 앱 전체에서 같은 duration/easing 토큰을 재사용한다. 기본은 bounce/elastic이 아닌 표준 ease-out으로 한다. 비용이 싼 속성(`transform`, `opacity`)만 애니메이션한다.
- **밀도** — 카드 안에 카드 안에 카드를 넣지 않는다. 깊이가 정당화되지 않으면 평평하게 만든다.
