## UI Consistency Audit

### 사용 시점
- 사용자가 UI/디자인을 점검·정리·"통일"해달라고 요청할 때.
- 그 영역에서 새 작업을 시작하기 전, 컴포넌트를 임기응변으로 여러 번 추가한 뒤.

### 절차
1. **범위를 정한다** — 점검할 화면/컴포넌트/폴더를 확인한다. 저장소 전체를 임의로 스캔하지 않는다.
2. **기준을 세운다** — 토큰의 현재 기준(Tailwind config, shadcn theme, 혹은 가장 일관되게 스타일링된 기존 컴포넌트)을 찾는다. 새 기준을 처음부터 지어내지 않는다.
3. **드리프트를 스캔한다** — 토큰 대신 쓰인 하드코딩된 색상/간격, 일관되지 않은 radius/shadow, 서로 다른 폰트 크기/굵기, 일관되지 않은 모션 duration/easing, 하나로 합쳐야 할 유사 중복 컴포넌트를 찾는다.
4. **파일별이 아니라 패턴별로 보고한다** — 각 이슈가 얼마나 퍼져 있는지 보이도록 묶는다 (예: 파일별 나열 대신 "6개 컴포넌트는 `rounded-xl`, 11개는 `rounded-lg` 사용").
5. **우선순위대로 수정안을 제시한다** (노출도가 높고 반복이 잦은 드리프트부터). 변경될 파일 목록을 보여주고 적용 전 확인을 받는다 — 한 번에 여러 파일을 건드릴 수 있으므로 (AGENTS §3, Surgical Changes 참조).
6. 확인된 수정만 적용하고, 나머지는 후속 작업 목록으로 남긴다.
