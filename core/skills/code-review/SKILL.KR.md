## Code Review

### 사용 시점
- 구현 직후, 커밋/PR 전에.

### 절차
1. 플랫폼이 지원하면 `code-reviewer` 서브에이전트를 호출한다 — 1순위 Opus 5, 2순위 Opus 4.8, 둘 다 안 되면 현재 세션과 같은 모델을 상속한다 — 변경된 파일/diff와 원래 요구사항을 함께 넘긴다.
2. 서브에이전트를 쓸 수 없는 환경이면, 아래 체크리스트로 직접 검토한다 — "방금 내가 쓴 코드"라는 사실을 의식적으로 제쳐둔다.
3. 결과를 반영한다: critical/high 등급 문제는 완료로 치기 전에 고치고, 의도적으로 미룬 항목은 남겨둔다.

### 체크리스트 (서브에이전트 없을 경우)
- **정확성** — 요구사항 만족? 엣지 케이스?
- **회귀** — 기존 동작을 깨뜨리지 않았는가?
- **테스트** — 새 로직에 테스트가 있는가? 빠진 케이스?
- **보안** — 입력 검증, 비밀값 노출, 인젝션 위험?
- **가독성** — 6개월 뒤의 내가 이해하는가?
