## TDD Workflow

### 주기
1. **인터페이스 정의** — 시그니처를 먼저 정한다.
2. **RED** — 플랫폼이 지원하면 `code-tester` 서브에이전트를 호출해서, 구현을 보지 않고 스펙/인터페이스만으로 테스트를 작성하게 한다. 지원하지 않으면 직접 실패 테스트를 작성하고 실패를 확인한다. (증거)
3. **GREEN** — 통과시키는 최소 코드를 작성한다.
4. **REFACTOR** — 중복 제거, 이름 정리. 테스트는 계속 통과.
5. **VERIFY** — build, lint, types, tests, 커버리지 80%+ 확인.

### 규칙
- 테스트 없이 프로덕션 코드를 먼저 쓰지 않는다.
- RED 단계를 건너뛰지 않는다.
- 스파이크·프로토타입 코드는 TDD를 생략할 수 있다. 실제 구현으로 채택되면 그때 테스트를 소급 작성한다.
